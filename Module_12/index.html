V8 Engine

Q. What is the V8 Engine?

Ans. V8 is Google's open-source, ultra-fast JavaScript and WebAssembly engine. It is written in C++ and serves as the core execution layer inside Google Chrome and Node.js runtime environments.

Q. Why is the V8 Engine important for Node.js?

Ans. Without V8, Node.js wouldn't exist as we know it. V8 acts as the heavy-lifting runtime engine that allows developers to run standard JavaScript code natively on physical servers and computers rather than keeping it sandboxed inside a browser window.

Q. What is the main responsibility of the V8 Engine?

Ans. Its main job is to take human-readable JavaScript code and instantly compile it into raw, native machine code that a computer's CPU can execute. It achieves this blazing speed via Just-In-Time (JIT) compilation.

Execution

Q. What is the difference between Synchronous and Asynchronous execution?

Ans. Synchronous means code runs sequentially, line-by-line. If one operation takes 10 seconds, the whole system freezes and waits for it to finish. Asynchronous means a time-consuming task is handed off to the system background, allowing the remaining code to keep executing immediately without pausing the main thread.

Q. What is the Call Stack?

Ans. The Call Stack is a data structure used by the JavaScript engine to keep track of function execution order. It works on a LIFO (Last-In, First-Out) mechanism. When a function is called, it gets pushed onto the top of the stack. When it finishes running, it gets popped off the stack.

Event Loop

Q. What is the Event Loop?

Ans. The Event Loop is a continuous loop mechanism that constantly monitors the Call Stack and the Callback Queue (where completed asynchronous tasks wait).

Q. Why is the Event Loop needed in Node.js?

Ans. Because JavaScript is strictly single-threaded (it only has one Call Stack and can only do one thing at a time). The Event Loop is required to orchestrate tasks so that heavy asynchronous background actions don't completely lock up the single main thread.

Q. How does the Event Loop help execute asynchronous code?

Ans. When an asynchronous background task (like a timer or file fetch) completes, its corresponding callback is placed into the Callback Queue. The Event Loop constantly waits until the main Call Stack becomes completely empty. The moment it detects an empty stack, it safely moves the first callback from the queue up into the stack to be executed.

libuv

Q.What is libuv?

Ans. libuv is an open-source C library that was specially written to give Node.js cross-platform access to the host computer's operating system capabilities.

Q. What types of tasks are handled by libuv?

Ans. libuv implements the underlying mechanism of the Event Loop and controls Node.js's internal Thread Pool. It handles heavy system-level asynchronous tasks such as File System I/O operations (fs), Network sockets/requests, and resource-heavy cryptography/compression utilities.
